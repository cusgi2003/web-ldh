# 📂 04. 인프라 아키텍처 및 기술 스택 (Tech Stack)

> **대규모 트래픽과 데이터가 유입되는 환경에서 실시간으로 데이터를 포착하고, 안정적으로 스트리밍하며 관제하기 위한 인프라 아키텍처 기술 스택입니다.**

---

## 🔄 1. 고성능 데이터 추출 및 패러다임 전환

### ⚡ CDC (Change Data Capture, 변경 데이터 포착)
* **정의:** 송신 시스템 DB에서 데이터가 생성, 수정, 삭제(CUD)되는 변경 사항만을 실시간으로 감지하여 추출하는 기술입니다.
* **장점:** 전체 데이터를 매번 주기적으로 퍼오는 방식(Full Dump)에 비해 원천 시스템 부하가 매우 적으며, 실시간 동기화 및 연계 파이프라인 구축에 최적화되어 있습니다.

### 📊 대용량 데이터 적재 패러다임 비교 (Data Warehouse)
운영 시스템으로부터 데이터를 추출하여 분석 전용 대용량 데이터베이스 저장소인 **데이터 웨어하우스(Data Warehouse)**에 모으는 핵심 데이터 엔지니어링 기법입니다.

| 비교 항목 | 🗂️ ETL (Extract, Transform, Load) | 🚀 ELT (Extract, Load, Transform) |
| :--- | :--- | :--- |
| **프로세스** | 추출 ──> **가공/정제** ──> 적재 | 추출 ──> **적재** ──> 필요 시 가공/분석 |
| **가공 시점** | 최종 시스템에 적재하기 **전**에 수행 | 데이터를 저장소에 **넣은 후** 필요할 때 수행 |
| **처리 방식** | 데이터 정제, 규격 통일, 암호화, 가공 처리를 별도의 스테이징 영역에서 완료 후 전송 | 원본 데이터를 그대로 대용량 클라우드 저장소에 먼저 적재하고, 고성능 클라우드 분석 엔진 연산력 활용 |
| **인프라 특징** | 데이터 가공용 별도 서버 필요, 저장 공간 절약 | 현대적 클라우드 환경 최적화, 유연한 원본 데이터 보존 |

## 🚀 2. 분산 메시징 및 이벤트 스트리밍 플랫폼

* **`Kafka`:** 고성능 분산 이벤트 스트리밍 플랫폼. 메시지 수신 시 메모리뿐만 아니라 **디스크에 순차적으로 저장 및 보관(Append-only Log)**하므로 장애가 발생해도 높은 데이터 신뢰성을 보장합니다.
* **`Pulsar`:** 멀티테넌시(Multi-tenancy) 구조와 컴퓨팅-저장소 분리 아키텍처를 지원하는 차세대 분산 메시징 및 스트리밍 플랫폼입니다.

### 💾 대용량 데이터 저장 포맷 구조
* **`Avro`:** 데이터를 가로(Row) 방향으로 차곡차곡 모아서 저장하는 행 중심 포맷입니다. 스키마 변경 대응이 유용합니다.
* **`Parquet` (파케):** 데이터를 세로(Column) 방향으로 그룹화하여 저장하는 열 중심 포맷입니다. 특정 컬럼만 선별 분석하는 작업에 효율적이며 압축률이 뛰어납니다.

## 📊 3. 시스템 모니터링 및 서비스 품질 관리

### 👁️ 실시간 통합 관제 시스템 스택
* **`ELK 스택`:** `Logstash`로 데이터를 수집·가공하고, `Elasticsearch`로 검색·분석하며, `Kibana`로 시각화하는 대용량 로그 관리 특화 오픈소스 기술입니다.
* **`Grafana`:** 시각화 및 데이터 분석 대시보드 인프라에 최적화된 오픈소스 플랫폼으로, 시계열 데이터 관제에 널리 쓰입니다.
* **`AWS CloudWatch`:** AWS 클라우드 환경에서 애플리케이션 및 인프라의 자원 상태와 로그를 실시간 관리하는 일체형 관리형 모니터링 서비스입니다.

### 🥇 QoS (Quality of Service, 서비스 품질)
* **개념:** 네트워크 및 시스템 환경에서 핵심적이고 중요한 트래픽(데이터)에 우선순위를 부여하는 기술입니다.
* **목적:** 대규모 트래픽 병목 현상이나 한정된 네트워크 자원 속에서도 특정 비즈니스 핵심 서비스의 성능과 신뢰성을 보장하기 위한 통제 메커니즘입니다.
