# 📂 05. 최신 API 동향 및 표준 프로토콜

## 🔌 1. 연계 기술 및 통신 유형 분류
* **실시간 API:** 필요할 때 즉각적인 답을 주고받는 1:1 대화 방식 (클라이언트-서버 직결).
* **메시지 큐:** 작업을 대기열에 쌓아두고 하나씩 꺼내 처리하는 1:1 번호표 창구 방식.
* **이벤트 스트리밍:** 시스템의 모든 변화를 연속적인 데이터 흐름(Stream)으로 다루는 실시간 수집 기술.
* **`Pub/Sub`:** 발행자(Publisher)가 특정 주제(Topic)에 메시지를 보내면, 구독 중인 다수의 수신자(Subscriber)에게 메시지가 동시 전달되는 1:N 방식.

## 🌐 2. 웹 API 패러다임의 변화

### 🚨 REST API의 한계 및 단점
1. **설계 표준의 한계:** 공식적이고 강제적인 표준 규약이 없어 개발자마다 설계 방식이 상이함.
2. **데이터 전송 비효율성:** 불필요한 데이터까지 응답받거나(`Over-fetching`), 필요한 데이터를 위해 여러 번 API를 요청해야 함(`Under-fetching`).
3. **구조적 제약:** 무상태성(`Stateless`)으로 인해 매 요청마다 인증 정보를 포함해야 하므로 통신량이 증가하며, 제한적인 HTTP 메서드(`GET`, `POST` 등)로 복잡한 연산 표현이 까다로움.

### 💡 보완 기술의 등장
* **`GraphQL`:** Meta가 개발한 데이터 쿼리 언어. 클라이언트가 필요한 데이터 구조를 직접 요청할 수 있어 REST API의 비효율성을 완벽히 보완.
* **`AsyncAPI`:** OpenAPI 명세를 비동기/메시징 아키텍처(Kafka 등) 프로토콜로 확장한 표준 명세서.
* **`오픈 API`:** 내부 시스템 데이터나 기능을 외부 개발자가 활용할 수 있도록 개방한 인터페이스.

## 🛡️ 3. 엔터프라이즈 솔루션 및 보안 표준
* **`API Gateway` 및 웹 서버:**
  * **`Kong`:** 경량화와 뛰어난 성능을 자랑하는 클라우드 네이티브 대표 API Gateway.
  * **`Apigee`:** 구글 클라우드의 기업용 풀스택 API 관리 플랫폼 (설계, 보안, 수익화 등 생명주기 관리).
  * **`NGINX`:** 트래픽이 과도하게 몰리는 환경 처리에 특화된 고성능 리버스 프록시 및 웹 서버.
* **`WSO2`:** 오픈소스 기반의 통합 API, 식별/인증/인가, 연계 미들웨어 플랫폼.
* **`OAuth2`:** 비밀번호 노출 없이 제3자 애플리케이션이 사용자의 데이터 접근 권한을 안전하게 위임받을 수 있도록 지원하는 글로벌 표준 프레임워크.
* **`ISO 20022`:** XML, JSON 기반으로 제정된 차세대 글로벌 금융 메시지 교환 표준 규격.
