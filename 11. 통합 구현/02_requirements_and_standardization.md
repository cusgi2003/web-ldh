# 📂 02. 연계 요구사항 분석 및 표준화

## 🔍 1. 연계 요구사항 분석
* **정의:** 시스템 연결 전 데이터 규격과 송수신 방식을 설계하는 단계
* **입력 산출물:** `시스템 구성도`, `응용 어플리케이션 구성도`, `ERD`, `테이블 정의서`
* **수행 활동:** 환경 파악 ──> 요구사항 수집(`인터뷰`/`델파이` 등) ──> 데이터 분석 ──> `인터페이스 정의서` 작성

## 🎯 2. 데이터 식별 및 표준화
* **목적:** 컬럼명, 데이터 길이, 코드 체계가 서로 다른 시스템의 기준을 사전에 일치시키는 작업

### 🔄 데이터 식별 3단계 규칙
1. **송/수신 데이터 식별:** 테이블 정의서를 분석하여 `타입`, `길이`, `PK 여부`, `NULL 허용 여부` 추출
2. **형식 정의:** 환경에 맞는 포맷 선정 (`JSON`: 표준·경량 / `XML`: 레거시·공공 / `CSV`: 대용량)
3. **코드 체계 매핑:** 상호 간 공통 코드가 다를 경우 일대일 변환 규칙 정의

### 📋 표준화 시 주요 점검 사항 (Checklist)
- [ ] **구조 매핑:** 항목명 1:1 일치 (예: `name` ──> `userName`)
- [ ] **길이 정합성:** 송신측 길이가 수신측보다 길면 데이터가 잘리므로(`Truncate`) 사전 조정 필요
- [ ] **정제 규칙:** 저장 전 공백 제거, 중복 제거, 포맷 통일 규칙 수립
