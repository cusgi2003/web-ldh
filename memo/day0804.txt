내외부 연계 모듈 구현 환경

내외부 연계
서로 다른 시스템에 데이터를 주곱다으면 함께 동작하도록 연결하는 것
최근 회사에서는 하나의 프로그램만 사용하는 경우가 거의 없다
예를 들어 쇼핑물에서는 회원관리 프고르ㅐㅁ. 주문 프로그램, 결제 시스템, 배송 시스템,
재고 시스템 등 여러 프로그램이 각각 존재한다

이 시스템들이 서로 정보를 주고 받아야 정상적으로 업무가 진행된다

내외부 연계 모듈 구현 환경
서로 다른 시스템간 데이터 교환 및 서비스 연계를 실현하기 위해
필요한 기술적 물리적 환경

-데이터베이스
- 인터페이스 테이블
- 프로그램
- API
- 네트워크
- 서버
- 보안
- 로그 시스템

구현 방식
1. DBMS 오브젝트
- Trigger
- Procedure
db 안에서 자동으로 실행되낟.

장점
- 구현이 비교적 쉽다
- 별도의 프로그램이 적다
- DB내부에서 처리하므로 속도가 빠르다
- 소규모 시스템에 적합하다

2. 프로그램 코드
- Java, Spring, Python 등으로 직업 구현한다
- 데이터를 추출하고 필요한 형태로 형변환 한 후 다른 시스템으로 
전송하는 몯느 과정을 개발자가 직접 구현한다
- DB연결, 데이터 조화, 데이터 금증, 데이터 변환, JSON or XML 생성,
API 호출, 로그 기록, 오류 처리

장점
- 개발이 쉽다ㅣ
- 다양한 언어와 플래폼에서 사용할 수 있다
- 확장성이 높드ㅏ
- 클라우드 환경에 적합하다
단점
- 네트워크 장애의 영향을 받는다
- 보안 설정이 중요하다
- API 버전 관리가 필요하다



5. API/클라우드 연계 방식
- 클라우드와 MSA 환경에서 REST API, gRPC, Kafka 등의 이벤트 스트리밍을 활용하여
시스템을 연계하며 API Gateway와 Service Mesh를 통해 서브시 간 통신, 보안, 모니터링을 관리한다

API Gateway : 여러 서비스로 들어가는 요청을 한 곳에서 받아서 적절한
서비스로 전달하는 안내 데스크 역할

Service Mesh : MSA에서 서비스 간 통신을 관리하는 기술

장점
- 확장성이 우수하다
- 경량 구조이다
- 실시간 이벤트 처리가 가능하다
단점
- 초기 아키텍처 설계가 복잡하다
- API 버전 관리가 필요하다
- 보안 체계가 필요하다
- 장애 추적이 어렵다

하이브리읃 연계
- 기존에 사용하던 온프레미스 시스템과 새롭게 도입한 클라우드 또는 SaaS 시스템을 함께 연결하는 방식
- 많은 기업이 기존 시스템을 한 번에 모두 클라우드로 이전할 수 없다
- 기존 시스템에는 중요한 데이터와 업무 기능이 많고, 교체 비용과 위험도 크기 때문이다.

DB 기반 + EAI
DB 기반 + API Gateway
EAI + API Gateway

장점
- 현실적인 이전 및 호가장 전력이 가능하다
- 기존 레거시 자산을 활용할 수 있다
- 클라우드 기능을 선택적으로 사용할 수 있다

단점
- 관리가 복잡하다
- 운영비용이 증가한다
- 데이터 일관성 관리가 어렵다
- 네트워크 의존성이 높아진다


내외부 연계 모듈 구현 환경의 필요성

1. 이기종 시스템 간 데이터 통합
- 시스템별로 사용하는 db가 다를 수 있다
- 이렇게 서로 다른 시스템을 하나로 연결해 주는 것이 연계이다

2. 업무 프로세스 자동화 및 효율성 제고
- 데이터 흐름 자동화와 실시간 또는 배치 처리가 가능하다
자동화 : 사람이 직접 입력하지 않아도 프로그램이 자동으로 처리하는 것
실시간 처리 : 주문이 즉시 처리된다
배치 처리 : 한 번에 모아서 처리한다

3. 안정성 및 오류 대응
오류 로깅, 예외 처리, 장애 복구를 통해 신뢰성을 확보한다.
오류 로깅 : 
예외 처리 : 오류가 발생해도 프로그램이 종료되지 않도록 처리
장애 복구 : 일시적인 장애가 발생하면 데이터를 다시 전송하거나 이전 상태로 복원한다

4. 확장성 확보
- 클라우드와 분산 호나경에서도 유연하게 연계할 수 있어야 한다
확장성 : 사용자가 증가하거나 서비스가 늘어나도 시스템을 쉽게 확장할 수 있는 능력

5. 표준화 및 상호 운용성
- Restful API, OpenAPI, JSON/XML 기반 데이터 포맷 활용 및 글로벌 표준을 준수하여
표준화 및 상호 운용성을 확보할 필요가 있다

6. 최신 동향 반영
- 이벤트 중심 아키텍처
- 서버리스 컴퓨팅
- AI 기반 연계 관리


연계 모듈 구현 환경 구축

1. 연계 모듈 구현 환경 변경 사항을 파악한다
먼저 연계 방식을 결정한다
- 테이블 방식 : 인터페이스 테이블을 이용하여 데이터를 전달
ㄴ 실시간 처리, 데이터 양이 많을 때 안정성 중시
- 파일 방식 : XML 같은 파일을 이용하여 연계 데이터를 전달
ㄴ 하루에 한 번 전송, 대량 데이터, 외부 기간

2. EAI/ESB 기반 연계 모듈 구현 환경 구축
2-1. 연계 DB 및 계정을 생성한다
운영 DB와 연계 DB의 목적이 다르기 때문에 분리하는게 원칙
2-2. 연계를 위한 테이블 생성
- 연계 데이터를 저장하는 연계 테이블
- 송수신 이력 및 오류 확인을 위한 로그 테이블
- 코드 매핑 및 변환을 위한 매핑 테이블
- 오류 처리를 위한 오류 코드 테이블
2-3. 연계 응용 프로그램 구현
송신 시스템이랑 수신 시스템에서 각각 구현
- 송신 시스템의 연계 응용 프로그램은 운영 DB에서 데이터를 추출하고
송신 시스템의 코드를 수신 시스템의 코드로 변환하는 작업
- 수신 시스템의 연계 응용 프로그램은 연계 테이블의 데이터에 대해 유효성을 점검하고,
운영 DB에 반영하는 작업 처리

3. 웹 서비스 방식에 의한 연계 모듈 구현환경 구성
웹서비스 : 인터넷이나 네트워크를 이용하여 서로 다른 시스템이 데이털르 주고받는 기술
SOAP(Simple Object Access Protocol)
XML 기반의 메시지를 HTTP, HTTPS, SMTP 등의 프로토콜을 이용하여 교환하는 기술
예전에는 대부분의 기업 시스템이 SOAP를 사용했고, 현재는 REST API 형식이 많이 사용되지만,
금융권과 공공기관의 기존 시스템에서는 아직도 SOAP을 사용하는 경우가 많다.
UDDI(Universal Description Discovery and Integration)
웹 서비스가 많아지면 어떤 서비스가 있는지 찾기 어렵다
그래섯 ㅓ비스 목록을 저장하는 저장소가 ㅍ리요하다
- 서비스 등록
- 서비스검색
- WSDL 저장

WSDL(Web Service Description Language)
웹 서비스의 상세 정보를 기술한 XML 문서
- 웹 서비스 이름
- 서비스 위치(URL)
- 메시지 형식
- 프로토콜 정보

3-2. 웹 서비스 방식에 의한 모듈 구현 환경 구축하기
- 송수신 파일 생성 위치 및 파일명 정의
송시시스템
송신 연계 파일
로그 파일
오류 로그파일

수신 시스템
수신 연계 파일
로그 파일
오류 로그 팡리

- 송신 시스템 연계 응용 프로그램 구현하기
ㄴ 송신 시스템의 운영 DB로부터 연계 데이터를 추출해서 송신 파일을 XMl 형식으로
생성하는 자바 프로그램 구현하기 
ㄴ 구현된 서비스를 주기적으로 싫애하기 위해 스케줄러에 등록한다

- 파일 전송 및 수신 시스템의 DB 반영 서비스 호출을 처리한다
ㄴ 웹 서비스 방식에서 파일 전송은 HTTP 기반의 SOAP를 사용하여 송수신한다
ㄴ 연계 파일을 수신 시슽메의 수신 위치로 전송한 후, 전송된 파일 내용을
수신 시스템 운영 DB에 반영하는 서비스를 실행한다

- 수신 시스템의 연계 응용 프로그램을 구현한다
ㄴ WSDL에 기술된 운영 DB에 연계 데이터를 반영하는 서비스를 구현한다
ㄴ 서비스 구현 방식은 송신 시스템의 연계 응용 프로그램과 동일하게 자바를 사용한다
ㄴ 구현한 서비스는 수신 시스템에서 서비스 호출이 가능한 위치에 배치한다.

연계 메커니즘 정의서 또는 연계 아키텍처 설계서를 확인 및 점검
연계 메커니즘 정의서란?
- 시스템 간 데이터를 어떻게 주고받을 것인지 구체적으로 정의한 문서

연계 메커니즘 동의서의 내용을 확인한다
- 송수신 시스템의 연계 응용 프로글매 구현 방식
- 연계 데이터 생성 방식
ㄴ 테이블 방식
ㄴ 파일 방식
- 코드 매핑 및 데이터변환 처리 위치
ㄴ 송신 시스템
ㄴ 수신 시스템

연계 메커니즘 정의서의 내용을 확인한다
연계 방식이 바뀌면 프로그램 구조도 달라지기 때문이다
예를 들어 REST API로 만들던 것을 파일(XML)방식으로 변경하면 프로그램을 새로 수정해야 한다

- 코드 매핑 및 데이터 변환 처리 위치
ㄴ 송신 시스템 : 송시 시스템에서 변환하는 경우가 많다.
송신 시스템이 데이터를표준 형식으로 만들어 보내면 수신 시스템의 부담이 줄어들기 때문이다
ㄴ 수신 시스템

연계 응용 프로그램 구현 방식을 수정 및 보완한다
처음에는 Trigger 방식으로 설계했지만 프로젝트가 진행되면서 Java프로그램이 더 적합할 수 있다
이 경우 정의서도 함께 수정해야 하낟
만약 정의서를 수정하지 않으면 개발자마다 달느 방식으로 구현하게 된다.

연계 데이터 생성 방식을 수정 및 보완한다
실시간으로 관리해야 하는 대량 데이터 -> 테이블
모아서 한 번에 보내는 대량 데이터 -> 

코드 매핑 테이블 생성 위치를 수정 및 보완한다
코드 매핑 테이블 생성 위치를 송싱 시스템의 운영DB로 연계 메커니즘 정의서에 수정 및 보완
송신 시스템에 두는 이유 : 송신 시스템에서 먼저 변환하면 수신쪽에서 변환 없이 바로 사용할 수 있다.
- 수신 시스템이 단순해진다
- 처리 속도가 빨라진다
- 코드 관리가 쉬워진다

연관된 내용을 일관되게 수정 및 보안한다
- 연계 응용 프로그램 구현 방식과 연계 데이터 생성 방식의 변경으로
영향을 받거나 연관된 부분이 있는지 확인하여 일관된 내용으로 수정 및 보완한다
- 문서와 실제 구현이 다르면 프로젝트 전체에 혼란이 발생한다

송신 시스템의 연계 모듈 구현 환경을 구축한다
1. DBMS 환경을 점검한다
- 송신용 데이터베이스 사용자 생성 여부
- 송신용 데이터베이스 사용자 및 비밀번호로 접근 가능한지 여부
- 데이터베이스 연결 상태
- 사용자 계정 권한
2. 송신 시스템의 테이블을 생성하고 데이터를 입력하낟
- 채용 공고 테이블
- 코드 테이블
- 코드 매핑 테이블
- 송신용 오류 코드 테이블

3. 송신 디렉터리를 생성한다
- 연계 파일, 로그 파일, 오류로그 파일이 위치할 송신 디렉터리를 생성한다
ㄴ 송싱 시스템의 연계, 로그, 오류 로그 파일에 대한 생성 위치및 파일명 부여 기준을 정의한다
ㄴ 정의한 각 파일 생성 위치 및 팡리명 부여 기준은 연계 메커니즘 정의서에 반영한다
ㄴ 연계, 로그, 오류 로그 파일이 위치할 디렉터리를 생성하고 접근 권한을 읽기와 쓰기로 부여한다

4. 송신 시스템의 팡리 정의서를 확인 및 점검한다
- 송신용 연계. 로그, 오류 로그 테이블 정의서 내용의 구조 ㅁ치 각  항목의
데이터 타입과 길이 등을 확인한다


수신 시스템의 연계 모듈 환경 구축

1. 데이터베이스 관리 시스템
- 수신용 데이터베이스 사용자의 생성 여부
- 수신용 데이터베이스 사용자 및 비밀번호로 접근 가능한지 여부
- 데이터베이스 연결 상태
- 사용자 계정 권한

2. 수신 시스템의 테이블을 생성하고 데이터를 입력한다
- 공고 정보 테이블
- 코드 테이블
- 수신용 오류 코드 테이블

3. 수신 디렉터리 생성하기
- 연계, 로그, 오류 로그 파일이 위치할 수신 디렉터리 생성하기

4. 수신 시스템의 파일 정의서를 확인 및 저검
- 각 테이블 정의서 내용의 구조 및 각 항목의 데이터 타입과 길이 등을 확인한다


송/수신 시스템의 연계 응용 프로그램을 개발한다.
1. 자바 개발 환경을 확인 및 점검한다
- 자바 개발 도구 설치 여부
- 설치된 자바 버전
- 설치 경고
- 환경 변수 설정 상태
- 정상적인 명령어 실행 여부


명령어와 옵션을 통해 설치된 자바 개발 도구의 버전을 확인할 수 있으며,
설치된 설치 경로 등 정상적인 설치 여부와 설치 환경을 확인한다

2. 송신 시스템의 연계 응용 프로그램 설계서를 작성한다
- 개발한 송싱 시스템 연계 응용 프로그램의 설계서를 작성한다
ㄴ 프로그램 명
ㄴ 인터페이스 파라미터
ㄴ 상세 처리 로직
ㄴ 오류 처리 방법
ㄴ 입출력 파일 정보

상세 처리 로직은 자바 언어의 문법으로 구체적이면 중요 내용의 누락없이 작성한다

송신 시스템 연계 응용 프로그램의 상세 처리 절차
1. 데이터베이스 연결 생성
2. 파일 생성
3. 데이터 추출
4. 코드
5. 데이터 변환
6. 연계 파일 기록
7. 처리 단계별 로그 기록
8. 오류 로그 기록

수신 시스템의 연계 응용 프로그램 설계서를 작성한다
1. 수신 시스템 연계 응용 프로그램의 설계서를 작성한다
2. 프로그램 설계서의 상세 처리 로직을 작성한다.

수신 시스템의 연계 응용 프로그램의 상세 처리 절차
1. 데이터베이스 연결 생성
2. 수신용 파일 생성
3. 수신용 연계 파일을 한 행씩 로드한다
- 수신용 연계 파일을 읽기모드로 열고, 파일의 데이털르 한 행씩 로드한다
4. 데이터를 각 속성으로 분할한다
- 파일에서로드한 데이터를 구분자인 콜론 ( : ) 을 기준으로 각 속성으로 분할한다
5. 각 속성의 데이터 유효성을 점건한다
- 비어있는 문자열 여부
- 필수 값 누락 여부
- 데이터 타입
- 데이터 길이
- 날짜 형식
- 숫자 형식
- 허용된 값인지 여부
6. 코드의 유효성을 확인한다
- 분할된 속성 중 코드가 존재할 경우, 해당 코드가 수신용 코드 테이블에
존재하는지 확인
7. 수신용 DB에 데이터를 반영한다
- 행의 모든 속성이 데이터 유효성 점검을 통과하여 유효한 경우 변경 구분자에
따라 수신용 DB의 공고 정보 테이블에 데이터를 반영한다
8. 처리 단계별 로그를 기록한다
- 연계 파일 열기
- 데이터 로드
- 각 속성 분할
- 데이터 유효성 점검
- 코드 유효성 확인
- 수신용 DB 반영
- 처리 완료
9. 처리 단계 별로 오류를 기록한다
- 처리 단계별로 오류가 발생하거나 데이터 유효성 점검 결과 유효하지 않은 값이
발견되면 수신용 오류 코드 테이브릉ㄹ 참고하여 수신용 오류 로그 파일에 기록한다

송수신 연계 응용 프로그램을 단독 배치형식으로 개발한다
- 작성한 송/수신 시스템의 연계 응용 프로그램 설계서 내용을 자바언어를 사용하여 
단독 배치 형식으로 개발한다
- 단독 배치 형식은 웹 화면이나 사용자의 직접 요청 없이 자바 프로그램이 독립적으로
실행되어 정해진 작업을 처리하는 방식이다.


연계 모듈은 여러 시스템을 연결하는 역할을 하기 때문에 작은 오류 하나만 발생해도 여러 시스템에
동시에 영향을 줄 수 있다.
1. 무결성
2. 업무 연속성 확보
- 장애나 오류가 발생하더라도 정상적으로 복구할 수 있는지 확인하고,
로그를 통해 처리 과정을 추적할 수 있는지 검증
3. 성능 및 확장성 검증
- 대량 데이터 전송이나 실시간 처리 과정에서 지연이나 병목 현상이 발생하는지 검토한다

병목현상 : 전체 시스템에서 가장 느린 부분때문에 전체 처리 속도라 느려지는 현상

확장성 : 사용자가 증가했을 때도 정상적으로 처리되는지 확인한다.

4. 보안성 검증
- 데이터 전송 구간 암호화, 접근 제어, 인증, 인가와 같은 보안 기능이 정상적으로 동작하는지 확인한다.

5. 최신 환경에서의 필요성
- 클라우드 및 MSA 기반 시스템에서는 수십 개에서 수백 개의 API와 서비스가 실시간으로 연계된다.
- 사람이 직접 하나씩 테스트 하는 것은 거의 불간으하다.
- 반복적인 테스트를 사람이 직접 수행하기보다는 자동화된 연계 테스트와
모니터링 체계를 구축할 필요가 있다

연계 모듈 테스트 설계는 무작정 테스트를 시작하는 것이 아니라 일정한 순서에 따라
체계적으로 수행한다

1. 테스트 범위 대상을 지정
- 테스트를 시작하기 전에 어디까지 테스트할 것인지와 무읏을 테스트 할 것인지를 먼저 결정한다
- 범위를 명확하게 지정하지 않으면 중요한 부분을 뺴먹거나 필요없는 부분까지
테스트하게 될 수 있다.

- 일반적으로 범위는 송신 시스템부터 수신 시스템까지 전체 데이터
전달과정으로 설정한다
- 테스트 대상 : 실제로 점검해야 하는 구성 요소

2. 테스트 케이스를 작성한다
- 연계 모듈이 정상저긍로 동작하는지 확인하기 위해 작성하는 구체적인
시험 항목이다
- 송신DB와 수신 DB의 테이블값 비교
- 송신 건수와 수신 건수 비교
- 코드 매핑 결과 확인
- 데이터 타입 및 길이 변환 확인
- 오류 코드 처리 여부확인
- 전송 후 로그 기록 여부확인
- 오류 발생 시 재처리 여부 확인

테스트는 다음과 같이 구분하여 설계할 수 있다
1. 단위 테스트
- 송신 시스템과 수신 시스템을 각각 개별적으로 검증하는 테스트
- 전체를 연결하기 전에 각각의 기능이 제대로 동작하는 지 확인하는 과정이다
- 송신 프로그램이 데이터를 정상적으로 추출하는가?
- 수신 프로그램이 파일을 정상적으로 읽는가?
- 코드 매핑 기능이 정상적으로 동작하는가?
- 데이터 유효성 검사가 정상적으로 수행되는가?

통합 테스트
- 송신 시스템부터 수신 시스템까지 전체 연계 흐름을 검증하는 테스트
- 모든 시스템을 연결하여 실제 운영환경과 비슷하게 테스트하는 것이다

3. 테스트 환경을 구축한다
- 테스트를 수행하기 위해서는 연계 모듈 실행에 필요한 환경을 미리 준비해야 한다
- 프로그램이 아무리 잘 만들어져 있어도 테스트 환경이 제대로 준비되지 않으면
정확한 결과를 확인할 수 없다.
- 컴퓨터 설치
- 시험 프로그램 설치
- 인터넷 연결
- 로그인 계정 준비
- 저장 공간 준비
- 테스트용 DB 생성
- 테스트용 테이블 생성
- 테스트용 파일 경로 설정
- 네트워크 방화벽 및 포트 설정
- 인증 및 보안 설정
- 로그 및 모니터링 환경 설정

4. 테스트를 수행한다
- 테스트 환경이 준비되면 설계한 테스트 케이스에 따라 실제로 테스트를 수행한다
- 데이터 전송, 오류 발생, 복구 절차 등을 실제 환경에서 수행하여 결과를 확인한다

정상 시나리오
-모든 조건이 정상적일떄도 제대로 동작하는가

비정상 시나리오
- 의도적으로 오류를 발생시켜 오류 처리 기능이 정상적으로 동작하는지 확인하는 테스트

5. 테스트 결과를 검증하고 기록한다
- 테스트를 수행한 후에는 예상 결과와 실제 결과가 일치하는지 검증하고, 그 결과를 기록해야 한다.
- 송신 데이터값과 수신 데이터 값 일치 여부
- 변환된 코드 값의 정확성
- 데이터 타입과 길이 변환 결과
- 오류 코드와 오류 메시지 기록 여부
- 로그 기록 여부
- 처리 시간
- 수신 DB 반영 여부

6. 리뷰 및 개선을 수행한다
- 테스트에서 오류가 발생되면 원인을 분석하고 수정한 후 다시 테스트해야 한다

회귀 테스트
- 수정 후에는 기존에 정상적으로 동작하던 기능에 새로운 문제가 생기지 않았는지 확인하기 위해 회귀 테스트를 진행
- 회원기능을 수정하는데 주문 기능이 오류 발생하면 안됨
- 그래서 수정한 부분뿐만 아니라 기존 기능도 다시 테스트함

- 연계 모듈 테스틑 여러 번 반복하는 경우가 많다
- 매번 사람이 직접 수행하면 시간이 많이 걸리고 실수도 발생할 수 있다
- JUnit, Postman, Jenkins, GitHub Actions, Apache JMeter 등의 도구를 활용하여 테스트를 자동화하면
더욱 빠르고 정확하게 테스트를 수행할 수 있다.

연계 모듈 테스트 설계 시 유의 사항
- 테스트를 수행하는 과정에서 데이터의 정확성, 오류 처리, 보안성, 성능, 운영 환경과의 유사성,
자동화지원을 고려해야 한다
- 이러한 사항을 충분히 고려하지 않으면 테스트에서는 문제가 없지만 
실제 운영 환경에서는 오류가 발생할 수 있다
1. 데이터정확성
- 연계 모듈 테스트에서 가장 중요한 것은 데이터가 정확하게 전달되는지 확인하는 것이다
- 데이터 값, 데이터 건수, 데이터 형식, 코드값, 날짜 형식, 필수 값
2. 오류 처리
- 예상하지 못한 오류갑 라생했을 때 다음 기능이 정상적으로 수행되는지 확인한다
- 오류 로그 기록, 오류 코드 반환, 오류 메시지 기록, 관리자 알림, 재처리, 롤백
- 중요한 것은 오류가 발생하지 않는 시스템이 아니라, 오류가 발생했을 때 올바르게 대응하는 시스템
3. 보안성
- 테스트 데이터에도 개인정보나 민감정보가 포함될 수 있으므로 보안 조치가 필요하다
- 개인 정보 마스킹, 데이터 익명화 , 접근 권한 제한, 테스트 계정 분리, 전송 구간 암호화
4. 성능 검증
- 연계 방식에 따라 서로 다른 성능 테스트를 수행해야 한다
실시간 연계
- 응답시간, 동시 요청 수, 초당 처리 건 수, 지연 시간
대용량 배치 연계
- 전체 처리 시간, 데이터 처리 건수, 메모리 사용랑, CPU 사용량, DB 부하
5. 운영 환경과 유사성 확보
- 테스트 환경이 운영 환경과 지나치게 다르면 테스트 결과를 신뢰하기 어렵다
6. 자동화 지원
- CI/CD 파이프라인과 연계하여 다음 작업을 자동화할 수 있다.
- 프로그램 빌드
- 테스트 실행
- 결과 수집
- 실패 알림
- 테스트 결과 대시보드 제공
- 회귀 테스트 실행

문제 1. 테스트 범위 및 대상 정의
시나리오

A 쇼핑몰은 고객이 주문하면 주문 정보가 연계 서버를 거쳐 ERP 시스템으로 전달되는 구조이다.

현재 개발자는 연계 모듈 테스트를 수행하려고 하지만, ERP DB만 테스트하면 충분하다고 주장하고 있다.

프로젝트 책임자는 송신 시스템부터 수신 시스템까지 전체 연계 과정을 테스트해야 한다고 설명하였다.

조건

다음 내용을 모두 포함하여 작성하시오.

테스트 범위를 작성하시오.
ㄴ 송신시스템(쇼핑몰)에서 주문 정보를 생성하여 연계 서버를 거쳐 수신 시스템(ERP)까지 전체 연계 과정.
테스트 대상 5가지를 작성하시오.
ㄴ 송신시스템, 연계 모듈, 연계 서버, 수신 시스템, REP 데이터베이스
ERP DB만 테스트해서는 안 되는 이유를 작성하시오.
ㄴ 송신시스템에서 데이터가 정상적으로 생성되었는지, 연계서버에서 데이터가 누락/변환 오류 없이 전달되었는지,
	통신 과정에서 오류가 발생하지 않았는지 확인할 수 없다.

문제 4. 테스트 환경 구축

회사는 테스트 비용을 줄이기 위해 운영 DB를 그대로 사용하여 연계 모듈 테스트를 수행하려고 한다.

또한 방화벽 설정도 확인하지 않은 상태에서 테스트를 시작하였다.

조건

다음 내용을 모두 포함하여 작성하시오.

운영 DB를 테스트에 사용하면 안 되는 이유를 작성하시오.
테스트 환경 구축 시 준비해야 하는 항목을 6가지 작성하시오.
테스트 환경은 운영 환경과 어떻게 구성해야 하는지 작성하시오.


운영DB는 실제 고객과 업무 데이터가 저장되어 있으므로 테스트 과정에서 데이터가 수정, 삭제, 중복 등록되면
실제 업무에 피해가 발생할 수 있다.
또한 비정상 데이터, 중복 PK, 필수값 누락 등의 오류 상황을 운영 DB에서 테스트하면 운영 서비스가 중단되거나
데이터의 무결성이 훼손될 수 있다.
따라서 테스트용 DB와 테스틍룡 데이터를 별도로 준비해야 한다

Adapter설치
연계 서버 설정
테스트용 DB와 테스트용 테이블 생성
테스트용 파일 경로 설정
네트워크 설정
방화벽 및 포트 설정

테스트 환경은 가능한 한 운영 환경과 유사하게 구성해야 한다. 운영체제, DBMS, 네트워크, 서버 사양,
보안 정책, 연계 솔루션 버전, 데이터 규모를운영 환경과 비슷하게 구성해야 한다
환경이 차이가 크면 테스트에서는 정상적으로 동작했지만 운영 환경에서는 
성능 저하나 호환성 오류가 발생할 수 있다

문제 5. 정상 시나리오와 비정상 시나리오
시나리오

회원 정보를 다른 시스템으로 전송하는 연계 모듈을 테스트하려고 한다.

프로젝트 팀장은 정상적인 데이터뿐 아니라 오류 상황도 반드시 테스트하도록 지시하였다.

조건

다음 내용을 모두 포함하여 작성하시오.

정상 시나리오 테스트 4가지를 작성하시오.
비정상 시나리오 테스트 6가지를 작성하시오.
비정상 시나리오 테스트가 필요한 이유를 작성하시오.

정상 시나리오 테스트
정상적인 회원 데이터가 수신 시스템으로 전송되는지 확인
회원코드가 약소고딘 코드로 정상적으로 매핑되는지 확인
수신된 회원 데이터가 수신 DB에 정상적으로 반영되는지 확인
전송 시작 시간, 완료 시간, 처리 결과가 로그에 정상적으로 기록되는지 확인

비정상 테스트 시나리오
- 네트워크 장애를 발생시켜 오류 처리와 재전송 여부를 확인
- DB Lock을 발생시켜 대기, 오류 기록 또는 재전송 여부를 확인
- 연계 서버를 중지하여 관리가 알림과 복구 후 재전송 여부 확인
- 회원번호나 이름과 같은 필스 값을 누라가여 오류 처리 여부를 확인
- 허용된 길이를 초과하는 데이터를 전송하여 오류 처리 여부를 확인

비정상 시나리오 테스트는 실제 운영 중 발생할 수 있는 장애와 잘못된 데이터에 시스템이 정상적으로 대응하는지
확인하기 위해 필요하다. 오류가 발생했을 때 로그 기록, 오류 코드 반환, 관리자 알림, 재처리, 롤백 등이
제대로 수행되지 않으면 데이터가 누락되거나 중복되고 업무가 중단될 수 있다
