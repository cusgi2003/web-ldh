- 어플리케이션의 기술적인 특성을 확인하고 배포 방식을 적용ㅎ나다
ㄴ 개발언어의 확인

ㄴ 애플리케이션의 유형을 확인한다
ㄴ 배포 대상 리소스의 유형 확인
ㄴ 배포 대상 리소스 유형을 확인한다
ㄴ 배포시 연계하여 처리하고자 하는 프로젝트 요건 확인

- 개발하려는 애플리케이션의 인프라 환경을 확인하고 배포 대상 서버를 확인
ㄴ 개발하려는 애플리케이션의 서버 구성 환경을 확인한다
ㄴ 리소스 유형별 배포 대상 서버를 확인한다
ㄴ 분산 배포 대상을 확인한다
ㄴ 통합 빌드 배포 구성도를 작성한다

애플리케이션 
1. 코드 인스펙션 
- 정적 테스트의 가장 일반적인 유형으로, 사전에 정의됰 코드 작성 규칙 기반으로 소스 코드를
점검하여 작성 규칙에 위반되는 소스코드를 추출하는 분석 도구
- 코드 인스펙션 Rul 유형
ㄴ 성능 개선 : 성능에 옇야을 미칠 수 있는 코드 저검
ㄴ 코듲 가성 규칙 : 개발 언어의 문법, 프로젝트 내에서 정의된 명명 규칙의 준수 여부
ㄴ 에러 발생 가능성 : 애플리케이션 동작 중 에러 발생 가능성이 있는 코드를 점검
- 코드 작성 Rule 심각도 구분
ㄴ 필수, Blocker : 에러 발생 간으성이 매우 높거나 메모리 누수가 발생하는 코드로, 반드시
수정되어야 하는 위반 사항
ㄴ 권고 상, Critical : 에러 발생 가능성이 높거나 일반적으로 수정되어야 하는
심각한 위반 사항
ㄴ 권고 중, MAjor : 에러 발생 가능성이 있거나 수정을 권고하는 중요 위반 사항
ㄴ 권고 하, Minor : 소스코드의 가독성, 유지보수성 향상을 위해 수정을 권고하는 위반 사항
ㄴ 정보, Info : 정보성으로 제공되는 위반 사항으로 개발자가 참고하여 적용할 수 있다.


변경되상이 되는 애플리케이션 소스를 형상관리 서버로부터 반출한다
1. 변경이 요구되는 대상 응용 프로그램, 개편 일정정 등을 
종합적으로 정리한 개편 계획서를 작성하여 관리자의 승인을 받는다.
2. 변경이 요구되는 자원을 반출하기 위한 반출 의뢰서를 작성하여 관리자의 승인을
받은 후 반출한다
