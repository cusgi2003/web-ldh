문제 13.

상황 A

application.jar 파일은 생성되었다.

상황 B

Console에는 다음 내용이 있다.

[INFO] Compiling...
[INFO] Running tests...
[INFO] Building jar...
[INFO] BUILD SUCCESS
상황 C

Log에는 다음 내용이 있다.

10:00:01 Build Start
10:00:05 Compile Success
10:00:10 Test Success
10:00:15 Package Success
10:00:16 Build Complete
문제
결과 파일이 생성되었다는 사실만으로 빌드 성공을 판단하는 것이 적절한지 설명하시오.
결과 파일 생성만으로 최종적으로 판단하는 것은 적절하지 않다
빌드 과정에서 실제로 어떤 단계가 수행되었고 정상 완료 되었는지 콘솔과 로그를 함께 확인해야 한다

Console과 Log의 역할을 각각 설명하시오.
Console
- 프로그램이나 빌드 도구가 현재 작업을 수행하면서 출력하는 실행 정보를 확인하는 영역
Log
- 빌드 과정과 결과를 시간, 단계별로 기록한 정보

빌드 완료 후 확인해야 하는 네 가지 핵심 결과를 작성하시오.
빌드 자체 결과 : 콘솔/로그
테스트 결과 : 성공/실패
테스트 커버리지 : 테스트가 실행한 코드 범위
코드 인스펙션 : 소스 품질 및 중요 위반 사항

BUILD SUCCESS라고 표시되었다고 하더라도 추가적인 확인이 필요한 이유를 설명하시오.

Compile : SUCCESS


Test

Passed    : 100
Failed    : 0


Coverage
UserService  : 95%
OrderService : 35%


Code Inspection
Blocker  : 0
Critical : 2
Major    : 9
Minor    : 20

프로젝트 기준:

Blocker  → 반드시 수정
Critical → 반드시 수정
Major    → 수정 권고
문제
테스트가 100% 성공했으므로 테스트가 충분하다고 판단해도 되는지 설명하시오.
충분하다고 판단할 수 없다
테스트가 100개 모두 성공했더라도 전체 코드가 아니라 일부만 테스트 했을 수 있다

OrderService에 대해 추가로 필요한 조치를 작성하시오.
커버리지가 35% 이므로 상당한 코드가 테스트 과정에서 실행되지 않았을
가능성이 있다.
커버리지가 낮음 -> 현재 테스트 케이스 검토 -> 테스트되지 않은 부분 확인
-> 다시 테스트 -> 커버리지 재확인

코드 인스펙션 결과를 근거로 빌드·배포를 계속 진행해도 되는지 판단하시오.
현재는ㄴ 그대로 진행하면 안된다
Critical이 2건 존재하고프로젝트 기준에서 Critical은 반드시 수정하도록 정의되어 있기 때문이다
따라서 개발팀에 수정 요청 후 다시 코드 인스펙션을 수행해야 한다

개발팀에 전달해야 할 내용을 구체적으로 작성하시오.
전체 테스트 결과 : 100 번 모두 성공
오더서비스 커버리지 : 35%
테스트 케이스추가 필요
Critical 2건 존재
Major 9건 존재
수정 후 테스트 및 인스펙션 재수행 필요

테스트 결과와 테스트 커버리지의 차이를 설명하시오.


문제 15.

통합 빌드에서 다음 네 문제가 각각 발생하였다.

상황 A

개발자가 OrderService.java를 Check Out하여 수정 중이며 아직 Repository에 Check In하지 않았다.

상황 B

모듈 관계가 다음과 같다.

Module A → Module B
Module B → Module A
상황 C

소스는 최신 버전이지만 application.properties가 이전 버전이다.

상황 D

다음 코드가 Repository에 Check In되어 있다.

public class UserService {


    public void saveUser() {
        System.out.println("save")
    }
}
문제
상황 A~D가 빌드에 어떤 문제를 일으킬 수 있는지 각각 설명하시오.
A : 개발자의 최신 수정본이 리포지토리에 반영되지 않으므로 통합 빌드에서 이전 버전의 오더서비스가
사용될 수 있다
B : 모듈 A와 B가 서로 호출하는 상호 참조 관계가 발생
C : 소스와 환경 설정 파일의 버전이 일치하지 않는다
D : 세미클론이 누락되어 있으므로 컴파일 오류가 발생하여 빌드가 실패할 수 있다

A~D에 대한 적절한 대응 방안을 각각 작성하시오.
A : 빌드 전 수정 완료된 모든 대상 소스가 체크인 되었는지 확인
B : 업무 모듈과 공통 모듈 등의 호출 방향과 의존 기준을 명확히 정의하여 상호 참조를 방지한다
C : 빌드 수행 전에 공통 파일과 환경 설정 파일을 최신 버전으로 업데이트하고 소스와 일관성이 
있는지 확인한다
D : 해당 개발자에게 컴파일 오류 내용을 전다랗고 소스를 수정하도록 요청한다

빌드 실패가 발생했을 때 담당자가 가장 먼저 확인해야 하는 정보를 작성하시오.
콘솔과 로그의 오류 정보를 확인해야 한다

빌드 담당자가 상황 D의 소스코드를 직접 수정하면 되는지 판단하고 이유를 설명하시오.
빌드 담당자가 직접 수정하는 것은 적절하지 않다
빌드 담당자의 역할은 오류를 확인하고 정확한 정보를 해당 프로그램을 개발한 개발자에게
전달하는 것이다

빌드 오류 발견부터 정상 빌드 확인까지의 전체 대응 흐름을 작성하시오.
빌드 -> 오류 발생 -> 콘솔/로그 확인 -> 오류 위치와 원인 분석 -> 담당 개발자에게 오류 정보 전달
-> 개발자 소스 수정 -> 개발자 Test -> 체크인 -> 리포지토리의 최신화를 확인 -> 다시 빌드 -> 테스트 결과 확인
-> 커버리지 확인 -> 코드 인스펙션 확인 -> 정상 여부를 확인
