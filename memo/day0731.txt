연계 오류
- 서로 다른 시스템 간 데이터를 주고받는 연계 과정에서 데이터가 정상적으로 전송, 수신, 저장, 처리되지 못해
발생하는 장애나 오류현상

연계 오류의 세가지 유형
- 연계 시스템 오류 : 인터넷이 끊기거나 연계 서버/수신 서버 컴퓨터가 꺼진 경우, 방화벽 포트 차단 등
네트워크 및 하드웨어/환경적 장애
- 연계 프로그램 오류 : 데이터 변환/매핑 프로그램의 버그, 파싱 실패, 연계 어댑터 프로그램 실행 오류 등
소프트웨어 로직 결함
- 연계 데이터 오류 : PK 중복, 필수값 누락, 코드 불일치, 데이터 타입 불일치 등 데이터 자체의 정합성/
무결성 결함

연계 오류 식별 방법
로그 파일 조회 : 연계 서버, 송수신 어댐터, db등의 로그 파일을 확인하여 오류 메시지 및 
오류 코드 식별
모니터링 시스템/관제 도구 활용 : 연계 모니터링 화면에서 미처리/실패 건 발생 알림 및 상태 값 확인
인터페이스테이블 조회 : 처리 상태 컬럼 조건을 통한 오류 건 검색

연계 오류 원인 분석 방법
오류 코드 및 메시지 해석 : 에러코드와 예외 추적 내역 분석
송/수신 데이터 비교 : 송신 전 데이터와 수신 수 변환/적재된 데이터 간 필드값, 규격, 코드값 차이 검증
통신/네트워크 연결성 점검 : Telnet, Ping, Curl 명령어로 IP/Port 차단 여부 확인

연계 오류 처리 및 재처리 방안
연계 오류 처리 절차
1. 오류 감지/인터셉트 : 시스템 이벤트, 모니터링 열람, 로그 모듈을 통해 에러 발생 즉시 감지
2. 오류 원인 규명 : 
- 데이터 오류 : 송신 데이터 보정 및 수신 DB 분기 로직(Insert/Update) 수정
- 프로그램 오류 : 변환/매핑 로직 수정 및 파서 업데이트
- 시스템 오류 : 네트워크 포트 오픈 및 재전송/재적재
3. 재처리 수행 : 실패한 건에 대해 재전송/재적재
4. 해결 여부 검증 및 이력 관리 : 모니터링 및 DB 조회로 최정 송공 확인 후 추적 관리 문서 작성
5. 재처리 실행 방식
- 자동 재처리 : 네트워크 순간 지연이나 서버 일시 부하 시 연계 엔진이 일정 간격으로 자동 재시도
- 수동 재처리 : 데이터 수정, 코드 매핑 등록, 방화벽 오픈 등 원인 해결 조치가 완료된 후 
관리자 관제 화면에서 [재처리/재시동] 실행
6. 연계 오류 추적 관리 및 예방 관리
- 오류 추적 관리 및 문서 작성 항목
ㄴ 인터페이스 ID 및 연계명
ㄴ 오류 발생 일시 및 대상 데이터 정보
ㄴ 조치 내용, 조치가, 조치 완료 일시
ㄴ 재처리실행 여부 및 최종 처리 결과
- 동일 문제 재발 방지 예방 관리 방안
ㄴ 표준 코드 체계 구축 및 중앙 매핑 관리 : 시스템 간 코드 일원화 및 매핑 테이블 관리
ㄴ 사전 데이터 검증 강화 : 송싱 전 필수값, 타입, PK 중복 여부를 체크하는 유효성 검증 로직 추가
ㄴ 네트워크/보안 정책 변경 사전 검토 : 방화벽 변경 전 연계 IP/Port 영향을 거증하는 프로세스 수립
ㄴ 실시간 관제 알림 체계 강화 : 장애 발생 즉시 담당자에게 알림이 발송되도록 구성

[문제 2] 데이터 저장 보안: DB 암호화 및 유출 시 무력화
시나리오

질문

DB 암호화가 적용되어 있을 때, 공격자가 데이터를 탈취하더라도 데이터가 보호되는 핵심 이유(데이터 탈취 무력화 개념)를 서술하시오.

DB 내 모든 컬럼을 암호화하지 않고 주민등록번호, 계좌번호 등 특정 민감 데이터만 선택적으로 암호화하는 이유를 성능 및 운영 측면에서 설명하시오.

- 탈취 무력화 : 데이터베이스 내 민감 정보가 암호화되어 저장되어 있으면, 공격자가 db전체를 탈취해도 복호화 키를 소지하지 않으면
해독하거나 악용할 수 없기 때문이다.
- 선택적 암호화의 이유 : 모두 암호화하면 시스템 성능이 크게 저하되고, 운영상 불편함을 느낀다.
따라서 민감도가 높은 정보위주로 암호화하고, 자주 사용하는정보는 성능과 보안의 균형을 맞춘다.

[문제 4] 데이터 무결성 확보: 암호화와 무결성 검증의 차이
시나리오
D 금융 시스템은 외부 결제 대행사(PG사)와 API 연계를 통해 주문 데이터(주문금액=100000)를 송수신하고 있습니다. 송수신 전 전송 구간 암호화(HTTPS)를 적용했으나, 내부 망을 통과하는 과정에서 악의적인 사용자가 데이터의 기밀성뿐만 아니라 주문 금액 자체를 1000으로 변조하여 전송할 수 있다는 우려가 제기되었습니다.

질문

"데이터 암호화"만 적용했을 때 데이터의 위변조를 완벽히 막기 어려운 이유를 기밀성(Confidentiality)과 무결성(Integrity) 개념을 비교하여 설명하시오.

연계 데이터가 전송 또는 저장 과정에서 변조되었는지 여부를 확인하기 위해 추가로 함께 적용해야 하는 무결성 검증 기술 2가지를 제시하고 그 작동 원리를 서술하시오.


- 암호화는 데이터 내용을 타인이 읽지 못하도록 숨기는 기밀성을 확보하는 기술이며, 내용이 원본대로 유지되었음을 보장하는 무결성과는 차이가 있다. 따라서 암호화만으로는 데이터의 일부가 위변조되었는지 검증하기 어렵다
- 해시 함수 : 원본 데이터로 해시값을 설정한 후 수신측에서 다시 계산한 해시값과 비교하여 일치 여부로 변조를 검증한다
- HMAC/전자서명 : 비밀키나 공인인증서를 이용해 데이터에 서명/인증 코드를 첨부함으로써 무결성 검증과 동시에
송신자의 신원확인까지 수행한다.

[문제 5] 클라우드 및 MSA 환경: 연계 데이터 보안 개념 및 아키텍처
시나리오
E 기업은 기존의 단일(Monolithic) 시스템을 클라우드 기반의 MSA(Microservice Architecture)로 전환 중입니다. 이에 따라 회원, 주문, 결제, 배송 등 여러 서비스 간에 API 호출을 통한 연계 데이터 통신이 실시간으로 빈번하게 발생하고 있습니다. 보안 담당자는 내부 서비스 통신이라도 절대 안전하다고 신뢰하지 않는 Zero Trust 관점의 연계 보안 아키텍처를 도입하고자 합니다.

질문

연계 데이터 보안의 기본 개념을 정의하시오.

MSA 및 클라우드 환경에서 서비스 간 연계 데이터 보안을 강화하기 위해 적용할 수 있는 대표적인 전송 구간 보안 기술 및 인증 방식을 2가지 이상 제시하고 그 필요성을 서술하시오.

- 서로 다른 시스템간 데이터를 송수신하는 과정에서 무단 접근, 탈취, 변조, 위변조 등을 방지하기 위해 전송구간과 저장 구간에 암호화 및 보호기술을 적용하는 모든 보안 활동

ㄴ mTLS : 기존 TLS가 클라이언트나 서버를 검증했다면, mTLS는 통신하는 두 서비스가 
	서로의 디지털 서명/인증서를 상호 검증한다. MSA 환경 내 내부 네트워크 구간이라도 Zero Trust 보안 모델을
	구현하여, 인가된 마이크로서비스 간의 통신만 허용하고 구간 내 데이터를 암호화 한다.
ㄴ  OAuth2 및 JWT : 서비스 간 API 통신 시 사용자/서비스의 자격 증명을 매번 DB에서 확인하지 않고, 전달받은 JWT의 서명을
	검증하여 빠르게 접근 권한을 확인한다. API 토큰 탈취및 무단 API 위조 호출을 차단하기 위해 필수적으로 적용된다.

ARIA : 2004년 국가정보원과 산학연 전문가들이 개발한 국가 표준 대칭키 블록 암호화 알고리즘
- 개발 배경 : 기존 SEED 알고리즘이 경량 환경이나 경량화 기기, sw 경량화 환경에서 효율이 떨어지는
	단점을 보완하고, AED 알고리즘과의 경량/경쟁 호환성을 위해 개발
- 주요 특징
블록 크기 : 128비트
키 길이 : 128, 192, 256 비트
구조 : SPN
장점 : 경량화 환경에 유리하며, 하드웨어 및 소프트웨어 구현 시 비트연산 위주로 동작하여 속도가 빠르고,
경량 기기에 적합하다

AES : 2001년 미국 표준기술연구소가 공모를 통해 지정한 세게ㅖ적 표준 대칭키 블록 암호 알고리즘이다.
- 개발배경 : DES의 키 길이가 짧아 해킹 위험이 높아짐에 따라 전 세계 표준으로 활용할 강력한 암호화 표준의
	필요성으로 탄생했다.
- 주요 특징
블록크기 : 128비트
키 길이 : 128, 192, 256비트
구조 : SPN
장점
- 안정성, 속도, 메모리 효율성이 뛰어나며 현재 전 세계 대부분의 연계보안에서 가장 널리 쓰이는 사실상의
글로벌 표준이다.

암호화 KEY를 관리하는 방식
1. KEY VALUT(키 볼트)
소프트웨어 기반의 클라우드 암호화 키/비밀정보 관리 서비스
보관 대상 : DB 암호화 키 뿐만이 아니라 API 인증키, 비밀번호, SSL/TLS 증명서 등 다양한 비밀정보를 한 곳에서 관리한다.
접근제어 : 어플리케이선 Key Vault에 접근할 때 정당한 권한이 있는지 확인한 후 키를 제공하거나,
Valut 내부에서 직접 암복호화를 수행해준다

대칭키 : 하나의 암호키로 암호화 복호화를 수행
장점
- 매우 빠르다
- 대용량 데이터에 적합
단점 
- 키를 안전하게 전달해야 한다

비대칭키 암호화 : 공개키를 통해 암호화하고 개인키이를 통해 복호화 한다
공개키(Public Key)
- 누구나 볼 수 있도록 공개된 키
- 데이터를 암호화 하거나, 전자서명을 검증할 때 사용
- 인터넷이나 연계 시스템을 통해 누구에게나 자유롭게 배포할 수 있다.
- 공개키로 암호화된 데이터는 오직 그와 짝을 이루는 개인키로만 복호화 할 수 있다.
- 공개키가 외부에 놏루되어도 해당 키로는 데이터를 복호화 할 수 없기 때문에 안전하다

개인키(Private Key)
- 소유자 본인만 안전하게 보관해야 하는 비밀 키
- 암호화된 데이터를 복호화하거나, 전저서명을 생성할 때 사용한다.
- 절대로 외부로 유출되어서 안되며, HSM이나 Key Vault같은 보안 저장소에 안전하게 보관해야 한다.
- 개인키를 분실하거나 유출당하면 암호화된 데이터가 해독되거나 타인이 나를 사칭할 수 있게 된다.
