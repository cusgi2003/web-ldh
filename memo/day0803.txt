통합구현의 정의
- 서로 다른 시스템이나 모듈을 연결하여 데이터를 주고받고, 하나의 서비스처럼
작동하도록 만드는 과정
- 사용자의 요구사항을 해결하기 위해 여러 시스템의 기능과 데이터를 연계 통합하여
하나의  서비스 환경을 구현함
- 송수신 방식, 아키텍처, 모듈 구현 등을 고려하여 시스템 간 데이터 교환 및 처리를 수행

통합구현이 필요한 이유
1. 이기종 시스템 간 데이터연계 필요성
2. 서비스 확장성과 재사용성 확보
3. 운영 효율성과 데이터 품질 향상
4. 신기 서비스 창출

통합 구현의 주요 기능과 요소
1. 데이터 생성 및 송신
2. 데이터 변환 및 매핑
3. 데이터 수신 및 정제
4. 연계 데이터 관리
5. 네트워크 및 프로토콜 관리

연계 요구사항 분석
- 시스템 연결 전 어떤 데이터를, 어떤 방식으로 주고받을 지 미리 결정하는
사전 작업

요구사항 분석을 해야 하는 이유
1. 사용자 요구사항을 구체화 하기 위해
2. 형식, 범위, 주기, 전송 방식 명확화
3. 확장성 및 오류 예빵
4, 서비스 품질 보장

연계 요구사항 분석 절차
1. 현행 시스템 및 운영 환경 파악(하드웨어, 소프트웨어, ERD 등)
2. 사용자 요구사항 수집(인터뷰, 설문조사, 체크리스트, FGI 등)
3. 연계 데이터 분석
4. 결과 정리(문서로 작성)

요구사항 분석에 앞서 필요한 입력물
- 시스템 구성도
- 응용 어플리케이션 구성
- ERD

출력물
- 요구사항 분석서 : 요구사항 ID, 유형, 내용, 제약/종료조건
- 인터페이스 정의서  : 연계 데이터 항목, 형식, 전송 방석, 주기 등을 명시
- 회의록 : 참석자, 논의 내용, 결정 사항 및 향우 일정 기록

연계 데이터 식별
- 서로 달느시스템이 데이터를 주고받기 우해 필요한 데이터를 찾아내고, 동일한 기준으로
정의하는 과정

연계 데딩터 식ㄱ별의 필요성
- 단순히 데이털르 전달하는 것을 넘어 데이터의정확성과 안정정적인 교환을 하기 위함
시스템 간 데이터 불일치 예방
- 시스템 간 데이터 불일치
- 코드 체계 불일치 문제 발생

연계 데이터 식별 절차
1. 연계 대상 데이터 추출 및 식별
2. 연계 데이터 매핑 및 변환 규칙 정의
3. 연계 데이터 식별자 정의
4. 연계 데이터 표준화 수행
5. 연계 데이터 명세서 작성

연계 방식
송/수신 시스템 간 데이터를 교환할 떄 정의할 내용
- 사용할 전송 프로토콜
- 사용할 데이터 형식
- 사용할 연계 미들웨어 또느 ㄴ연예 엔진




인터페이스 테이블
- 데이터를 다른 시스템에게 전달하기 위해 별도로 만든 데이터베이스 테이블

키의 관리
- 암호화된 데이터와 복호화 키를 같은위치에 보관하면 공격자가 둘을 함께 탈취할 수 있다.
- 키 사용 기록 저장
- 오래된 키 폐기


암호화 복호화의 필요성
- 데이터 탈취 무력화
ㄴ 공격자가 데이터를 훔쳐가더라도 내용을 해석하거나 활용하지 못하게 만드는 것을 의미한다
ㄴ 암호화되지 않은 데이터는 유출되는 즉시 공격자가 사용할 수 있다.

DB내 데이터 노출 차단
- 데이터베이스에는 개인정보, 금용정보, 인증정보 등 중요한 데이터가 저장된다.
- 데이터베이스 접근 권한이 잘못 설정되거나 관리자 계정이 탈취되면 저장 데이터가 노출될 수 있다.

연계 데이터 보안 적용하기
전송 구간 보안 방식을 결정한다
1. TLS(HTTPS)
2. Mutual TLS
3. SSH(Secure Shell)

송수신간 물리적 방 분리 방식을 결정한다
- 물리적으로 네트워크를 분리하는 방법

VPN(Virtual Private Network 가상사설망) 보안방식을 결정한다
- 인터넷 위에 전용 통신망을 만드는 기술
- 실제로는 인터넷을 사용하지만 암호화된 터널을 만들어 안전하게 통신한다
- 재택근무, 클라우드에서 많이 사용한다
- 구축비용이 저렴하고 인터넷만 있으면 사용이 가능하다
- 인터넷 품질 영향을 받는다

데이터 보안 방식 파악하기
1. 데이터 암호화 대상을 식별한다
개인식별 정보 : 이름, 주민번호, 주소, 연락처 ...
금용정보 : 계좌번호, 카드번호, 신용정보 ...
시스템 정보 : 운영 정보, 로그 ...

2. 암호화 복호화 구성 요소
- 암호화 알고리즘
SEED, ARIA, AES
- 암호화 키
- 아뫃화 복호화 라이브러리

3. 암호화 복호화 처리 프로세스 파악하기
- 암호화 프로세스
ㄴ 암호화 대상 데이터를 파악한다
ㄴ 암호화 알고리즘을 선정한다
ㄴ 암호화 Key를 관리한다 : key vault, HSM
ㄴ 암호화 라이브러리를 적용한다
ㄴ 암호화 문을 저장한다
- 복호화 프로세스
ㄴ 암호화 KEY 확인
ㄴ 암호문 로드
ㄴ 복호화 수행
ㄴ 평문 사용

4. 암호화 복호화 알고리즘 방식 파악하기
- 대칭키 암호화 : 하나의 키로 암호화와 복호화를 수행
- 비대칭키 암호화 : 공개키로 암호화를 하고 개인키로 복호화를 수행한다

5. 연계 데이터 암호화 방식을 위한 결정 사항을 파악한다
- 어떤 데이터를 암호화 할 것인가?
- 어떤 알고리즘을 사용할 것인가?
- 키는 어떻게 관리할 것인가?
- 어느 구간에서 암호화 할 것인가?
- 어느 구간에서 복호화 할 것인가?

6. 암호화 대상 속성의 데이터 길이를 수정한다
- 암호화 하면 데이터 길이가 증가할 수 있기 때문이다.

7. 암호화 알고리즘 라이브러리를 확보하여 설치한다.
- 송/수신 시스템에서 사용할 암호화 라이브러리 API를 설치한다.

8. 연계 응용 프로그램에서 암호화 복호화를 적용한다
- 송신 시스템에서 암호화 API 호출
- 수신 시스템에서 암호화 API 호출
- 수신 시스템 운영 DB에 별도의 암호화 알고리즘이 적용된 경우
ㄴ 송신 시스템의 암호화 방식으로 복호화한다
ㄴ 수신 시스템 운영 DB의 암호화 방식으로 다시 암호화 한다
ㄴ 새로 암호화된 데이터를 운영 DB에 저장한다.
