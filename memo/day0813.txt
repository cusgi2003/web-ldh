결함 조치 우선순위 결정하기
1. 결함에 대한 개선 방안 확인
- 테스트 목록을 확인한다
- 결함 목록의 세부 사항과 개선 방안을 확인한다
- 결함에 대한 내용을 파악하고 결함 유지를 정의한다
- 결함 관리 대장을 확인하고 결함 유형을 분리한다
- 개선할 테스트 케이스 ID를 선정한다
- 개선 조건과 범위를 설정한다
- 결함 유형별로 개선 효과를 정의한다

2. 개선방안에 대한 우선순위를 겨렂ㅇ
- 업무별 기준에 가중치를 부여한다
ㄴ 평가항목, 가중치에 대한 퍼센티지를 부여
ㄴ 옵무마다 등급(1~5) 부여
- 업무/서비스 중요도를 파악하기 위해 이전 시스템의 접속 로그와 
업무 일일 데이터 처리량을 통해 작성한다
- 시스템 의존도는 시스템 없이 수작업이 가능한 업무와 불가능한 업무로 나누어 작성한다
- 사용자 범위는 형재 사용 대상의 범위와 향후 변경되는 시스템의
확대 가능성을 팓단하여 수정
- 월 이용자 수는 현재 전담 인력과 ㅌ공통 성분을 포함화여 월 이용자 수를
산정하고 전체적인 평균치를 고려해야 한다
- 단위별 평가 등급을 부여한다
- 단위 업무별 심각도 계간
ㄴ 각 ( 평가항목 x 가중치)의 합산
ㄴ 가중치의 심각도를 측정하기 위해 표시 단위와 측정 구간 정의
High : H로 표시
Medium : M을 표시
Low : ㅣ로 표시
- 부여된 가중치와 심각도를 고려하여 우선선위를 결정한다
ㄴ 정량적으로 타나난 결함 심가도를 바탕으로 결함 조치의 우선순위를 나열한다
ㄴ 업무 별로결함 심각도가 가장 높아다고 해서 그 결함을 
무조건 수행하하는 것은 아니다
ㄴ 결함 우선순위를 긴급, 높음, 보통, 낮음 순으로우선 정렬하고
각 우선순위에 따라 인력 배치와 조치 일정을 결정한다





코드 인스펙션의 프로세스
자동 수행 : 사람이 모여 코드를 검토하기 전에 검사할 범위를 결정하고 도구 등을 활용하여
사전 검사를 수행하는 영역
- 범위 계획 : 어디까지 검사할꺼냐(인스펙션 대상, 검사 범위, 범위 선정 기준 결정)
- 시작 : 정해진 범위를 대상으로 자동 인스펙션을 수행한다

준비 단계 : 본격적인 인스펙션 회의를 하기 전에 사람이 검토할 수 있도록 필요한 자료와
계획을 준비하는 영역
- 준비 : 인스펙션 계획서, 체크리스트, 인스펙션 일정 공지, 참여자 결정, 검토할 소스 코드 준비,
관련 설계서 준비, 자동 검사 결과 준비
이행단계 : 계획한 인스펙션을 실제로 수행하는 것
인스펙션 회의 : 코드를 그 자리에서 수정하는 것이 아니라 결함을 찾아내고 기록하는 것

시정조치 : 발견한 문제를 수정하고 제대로 수정되었는지 확인하는 영역
- 재작업 : 인스펙션에서 발견된 결함을 원래 코드를 작성한 개발자가 수정한다
- 후속처리 : 제대로 수정했는지 확인해야 한다

워크스루 : 작성자가 자신이 만든 소스 코드, 설계서 요구사항 등의 내용을 검토자들에게 설명하고,
참석자들이 질문이나 의견ㅇ르 제시하면서 오류를 찾아내는 방법
